# 制造智能技术课程设计报告

## 基于深度学习的工业产品表面缺陷智能检测系统

---

## 摘要

本课程设计运用 vibe coding 方法，开发了一个面向制造/工业场景的 B/S 架构智能检测系统。系统以热轧钢带表面缺陷检测为应用场景，集成 ResNet50 分类模型和 YOLOv8 目标检测模型，实现工业产品表面缺陷的自动化识别与定位。系统采用 Flask 后端 + 原生前端 + SQLite 数据库的技术栈，支持图片上传检测、历史记录管理、统计分析和模型管理等功能。全程使用 AI 编程工具辅助开发，保留了完整的 prompt 会话日志和 Git 提交记录。自动化测试覆盖 25 个测试用例，全部通过。

**关键词**：深度学习；表面缺陷检测；卷积神经网络；YOLOv8；Vibe Coding；B/S 架构

## 一、背景调研

### 1.1 研究意义

制造业是国民经济的主体，产品质量检测是制造过程中的关键环节。传统的人工目视检测存在以下问题：
- **效率低下**：人工检测速度慢，难以匹配高速生产线
- **一致性差**：检测结果受人员疲劳、经验差异影响
- **漏检率高**：微小缺陷难以肉眼识别
- **数据孤岛**：检测结果难以数字化管理和追溯

随着深度学习和计算机视觉技术的发展，基于 AI 的自动化缺陷检测成为制造业智能化转型的重要方向，具有显著的经济价值和研究意义。

### 1.2 国内外研究现状

**传统机器视觉方法**主要基于阈值分割、边缘检测和手工特征（SIFT、HOG）+ SVM 分类，可解释性强但对复杂背景鲁棒性差。

**深度学习方法**已成为主流：
- 分类网络：ResNet、EfficientNet 用于缺陷分类
- 目标检测：YOLO 系列、Faster R-CNN 用于缺陷定位
- 语义分割：U-Net 用于像素级缺陷分割
- 异常检测：PaDiM、PatchCore 用于缺陷样本稀缺场景

**工业应用**方面，康耐视、基恩士等推出商用 AI 视觉系统，国内华为、海康威视等也提供相关解决方案。开源框架 MMDetection、YOLOv8 等大幅降低了开发门槛。

### 1.3 技术方向映射

本项目涉及《制造智能技术基础》课程的 4 个技术方向：

| 技术方向 | 课程章节 | 在系统中的应用 |
|---------|---------|--------------|
| 深度学习与卷积神经网络 | 深度学习与神经网络 | ResNet50 分类、YOLOv8 检测 |
| 计算机视觉与图像处理 | 机器视觉与图像处理 | 图像预处理、数据增强、结果可视化 |
| 机器学习与模式识别 | 机器学习基础 | 模型训练、评估、超参数优化 |
| 智能制造系统与架构 | 智能制造系统 | B/S 架构设计、API 接口、流程集成 |

## 二、方案设计

### 2.1 系统总体架构

系统采用经典三层 B/S 架构：

```
┌─────────────────────────────────────────┐
│              表现层（前端）               │
│  登录页 / 检测页 / 历史记录 / 统计仪表盘   │
│  HTML + CSS + JavaScript + Bootstrap     │
└──────────────────┬──────────────────────┘
                   │ HTTP/RESTful API
┌──────────────────▼──────────────────────┐
│            业务逻辑层（后端）             │
│  Flask Web 框架                          │
│  ┌────────┬────────┬────────┬────────┐ │
│  │ 认证模块 │ 检测模块 │ 记录模块 │ 统计模块 │ │
│  └────────┴────────┴────────┴────────┘ │
│  ┌────────────────────────────────────┐ │
│  │         算法模块（推理引擎）          │ │
│  │  预处理 → 分类 → 检测 → 后处理 → 可视化 │ │
│  └────────────────────────────────────┘ │
└──────────────────┬──────────────────────┘
                   │
┌──────────────────▼──────────────────────┐
│              数据层                      │
│  SQLite 数据库  +  文件系统（图片存储）    │
└─────────────────────────────────────────┘
```

### 2.2 技术栈选型

| 层级 | 技术 | 选型理由 |
|------|------|---------|
| 前端 | HTML5 + CSS3 + JS + Bootstrap 5 | 轻量、无需构建工具、适合课程设计 |
| 图表 | ECharts | 功能强大、中文文档完善 |
| HTTP | Axios |  Promise 风格、拦截器支持 |
| 后端 | Python + Flask | 轻量 Web 框架、AI 生态完善 |
| 深度学习 | PyTorch + torchvision | 动态图、研究社区活跃 |
| 检测 | Ultralytics YOLOv8 | 工业界主流、API 简洁 |
| 图像处理 | OpenCV + Pillow | 功能全面、性能优秀 |
| 数据库 | SQLite + SQLAlchemy | 零配置、ORM 支持、适合小型应用 |

### 2.3 算法方案

**分类模型**：ResNet50 + ImageNet 预训练迁移学习，替换最后一层全连接层为 6 分类输出。训练策略：前 10 轮冻结骨干网络，后 20 轮全网络微调。

**检测模型**：YOLOv8s，使用 COCO 预训练权重，在 NEU-DET 数据集上微调 100 轮，batch=16，输入尺寸 640×640。

**检测流水线**：图像预处理 → 分类判断是否有缺陷 → 如有缺陷则检测定位 → NMS 后处理 → 坐标映射 → 结果可视化。

### 2.4 数据库设计

详见《方案设计.md》第 3.6 节，包含 users、detection_records、defect_details 三张核心表。

## 三、数据资源构建

### 3.1 数据集来源

使用 **NEU-DET 热轧钢带表面缺陷数据集**，由东北大学工业自动化实验室发布：
- 下载地址：https://www.kaggle.com/datasets/kaustubhdikshit/neu-surface-defect-database
- 规模：1800 张灰度图像（200×200），6 类缺陷，每类 300 张
- 标注：PASCAL VOC XML 格式边界框

### 3.2 缺陷类别

| 编号 | 英文名称 | 中文名称 | 数量 |
|------|---------|---------|------|
| 0 | crazing | 裂纹 | 300 |
| 1 | inclusion | 夹杂 | 300 |
| 2 | patches | 斑块 | 300 |
| 3 | pitted_surface | 麻点 | 300 |
| 4 | rolled-in_scale | 氧化皮 | 300 |
| 5 | scratches | 划痕 | 300 |

### 3.3 数据预处理

编写了完整的预处理脚本 `data/preprocess.py`，实现：
1. **数据清洗**：校验图片与标注对应关系
2. **格式转换**：VOC XML → YOLO TXT（归一化中心坐标+宽高）
3. **数据集划分**：按 7:2:1 分层抽样，保证各类别比例一致
4. **图像归一化**：统一 resize 到 640×640
5. **配置生成**：自动生成 YOLOv8 训练用 dataset.yaml

### 3.4 数据增强

训练时在线数据增强：
- 随机水平/垂直翻转（概率 0.5）
- 随机旋转（±15°）
- 亮度扰动（±20%）
- Mosaic 增强（YOLOv8 内置）

## 四、系统实现

### 4.1 后端实现

后端基于 Flask 框架，采用蓝图（Blueprint）模块化设计：

| 模块 | 文件 | 功能 |
|------|------|------|
| 应用入口 | src/app.py | Flask 应用创建、路由注册、数据库初始化 |
| 配置 | src/config.py | 集中管理所有配置项 |
| 认证 | src/routes/auth.py | 注册、登录、登出、用户信息 |
| 检测 | src/routes/detect.py | 单张/批量图片上传检测 |
| 记录 | src/routes/records.py | 记录列表、详情、删除、导出 |
| 统计 | src/routes/stats.py | 概览统计、趋势、分布、模型性能 |
| 模型管理 | src/routes/model_manage.py | 模型列表、阈值配置（管理员） |

**核心检测接口流程**：
1. 接收上传文件，校验类型和大小
2. 保存原始图片到 uploads/original/
3. 调用检测流水线执行推理
4. 保存结果标注图片到 uploads/result/
5. 保存检测记录和缺陷详情到数据库
6. 返回 JSON 结果（含结果图片 URL）

### 4.2 算法模块实现

算法模块位于 `src/algorithms/`，采用单例模式管理模型实例：

```
algorithms/
├── preprocess/image_preprocess.py   # 图像加载、Letterbox、归一化
├── models/classifier.py             # ResNet50 分类器（含模拟推理降级）
├── models/detector.py               # YOLOv8 检测器（含模拟推理降级）
├── inference/pipeline.py            # 检测流水线（分类+检测整合）
├── postprocess/visualize.py         # 边界框绘制、标签渲染
├── train_classifier.py              # 分类模型训练脚本
├── train_detector.py                # 检测模型训练脚本
└── evaluate.py                      # 模型评估脚本
```

**模拟推理降级设计**：当模型权重文件不存在时，系统自动切换到基于图像纹理特征（边缘密度、局部方差、亮度分布）的启发式模拟推理，保证系统在未训练模型时也能完整运行和演示。这一设计确保了课程演示的可靠性。

### 4.3 前端实现

前端采用原生 HTML + CSS + JavaScript + Bootstrap 5，无需构建工具：

| 页面 | 模板 | 功能 |
|------|------|------|
| 登录页 | login.html | 用户登录 |
| 注册页 | register.html | 用户注册 |
| 检测主页 | index.html | 图片上传、检测、结果展示 |
| 历史记录 | records.html | 记录列表、筛选、详情、删除、导出 |
| 统计仪表盘 | stats.html | ECharts 图表展示（趋势、分布、性能） |
| 模型管理 | models.html | 模型列表、阈值配置（管理员） |

**检测页交互**：支持点击和拖拽上传，实时预览原图，可切换快速/精确模式，调节置信度阈值，结果展示包含标注图片、统计卡片、概率分布图和缺陷详情表。

### 4.4 数据库实现

使用 SQLAlchemy ORM 操作 SQLite 数据库，定义三个模型类：
- `User`：用户信息，密码使用 Werkzeug 哈希存储
- `DetectionRecord`：检测记录，缺陷类型以 JSON 数组存储
- `DefectDetail`：缺陷详情，关联检测记录，存储边界框和面积

### 6.2 关键 Prompt 策略

1. **角色设定**：明确指定"你是一位资深全栈开发工程师"或"你是一位计算机视觉算法工程师"
2. **任务拆解**：将复杂功能拆分为小模块，逐个生成
3. **约束说明**：明确技术栈、代码规范、输入输出格式
4. **验收标准**：提供测试用例或预期结果描述
5. **上下文提供**：在生成代码前提供相关文件内容和项目结构

完整的 AI 对话记录保存在 `prompt/` 目录下，共 3 个会话 JSON 文件。

### 6.3 AI 出错案例及纠正过程

**案例 1：数据预处理坐标转换错误**
- AI 初始生成的 VOC→YOLO 坐标转换未考虑 resize 后的尺寸变化
- 纠正：在代码审查中发现，增加了基于目标尺寸重新归一化的逻辑，并增加了边界裁剪和无效框过滤

**案例 2：测试环境数据库冲突**
- AI 生成的 pytest fixture 使用临时文件数据库，导致测试间数据残留
- 纠正：改用内存数据库 `sqlite:///:memory:`，并在每次测试前 drop_all + create_all

**案例 3：Flask 静态文件路由**
- AI 初始方案将上传图片放在 static 目录，与源代码混在一起
- 纠正：设计独立的 uploads 目录，并添加专门的路由函数 serve_upload 提供访问

### 6.4 人工接管说明

所有 AI 生成的代码均经过人工审查和理解，核心算法逻辑（检测流水线、坐标映射、NMS）已逐行验证。数据库设计、API 接口规范由人工制定后交由 AI 实现。

### 7.2 创新点

1. **双模型架构**：分类+检测级联，兼顾速度和精度
2. **模拟推理降级**：无模型权重时自动切换启发式模拟，保证系统可运行

2. **性能优化**：可引入 ONNX Runtime 或 TensorRT 加速推理
3. **功能扩展**：可增加批量异步检测、实时视频流检测、缺陷严重程度分级等功能
4. **部署优化**：可使用 Docker 容器化部署，支持生产环境扩展
